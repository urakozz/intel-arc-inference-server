# Spec 1.5 - Decode Performance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the measured 23.73 → 31.50 t/s gap (or produce the priced
re-assessment memo that says exactly why not) via an in-situ per-kernel
profiler, an early vLLM cross-check, and a profile-ranked lever ladder under
the hard golden gate.

**Architecture:** Stage 0 builds the instrument - L0 kernel-timestamp events
on the captured 645-launch list (`docs/15-step-anatomy.md` is its output) -
and runs the vLLM three-way cross-check. Stage 1 works five levers in
profile-ranked order, each an independent task with identical acceptance
(suite green + golden gate 96/96 + profiler attribution + bench row).
Task 10 is the gate: win → record and tag; short → memo to the user.

**Tech Stack:** C++17, Level Zero (events added), OpenCL C 3.0 via ocloc AOT,
ctest on the box (box, `tools/box.sh`).

**Spec:** `docs/superpowers/specs/2026-08-25-spec1.5-decode-performance-design.md`
(read it first; §1's arithmetic calibrates every decision here).

## Global Constraints

- **Golden gate hard:** every accepted change keeps 96/96 tokens exact
  (`ctest -R golden_gate`); a token flip is stopped and surfaced, never
  accepted (spec §2).
- Full suite green (32+ tests) before every commit that touches src/.
- Determinism: no fp atomics, fixed grids/reduction orders, byte-identical
  replay; per-op bf16 RNE discipline in any restructured kernel; NO
  `-cl-denorms-are-zero` (build already fatals on it);
  `-cl-fp32-correctly-rounded-divide-sqrt` stays the ocloc default.
- **Launch-count ripple rule:** any task that changes the per-token launch
  count updates, in the same commit: `tests/runtime/replay_determinism_test.cc`
  (`CHECK_EQ(cap.kernel_count, 645)`), docs/04's "645 kernels" text, and
  docs/12's partition table. 645 is pinned in three places today.
- Profile mode NEVER produces a bench row; bench rows come from an event-free
  list and name the sha of the measuring binary.
- Every number in every doc labelled measured vs estimated. docs/12 mechanism
  text updated in the same commit as any kernel change.
- Box workflow: `tools/box.sh sync|build|test|run`, JOBS=44. Verify your files
  recompile after sync (rsync 1-s mtime granularity, BOTH directions - a
  box-side revert restores an older mtime than the built `.o`; `touch` and
  rebuild when in doubt).
- C++17, `-Wall -Wextra -Werror`; Linux only; server never downloads models.
- Work directly on `main`; nothing pushed; tags local. Checkpoint for all
  GPU tests: `Vishva007/Qwen3.8-27B-W4A16-AutoRound-GPTQ` (HF cache on box).
- Tasks 5-9 execute in **docs/15's ranked order** (Task 3's output). The
  controller re-orders them and may skip a lever whose measured share cannot
  repay its cost - one ledger ruling per skip. Task 10 always runs.

```cpp
// src/l0/event.h
#pragma once
#include <cstdint>
#include "l0/context.h"

namespace l0 {
// Pool of host-visible kernel-timestamp events. One pool, N slots.
class EventPool {
 public:
  EventPool(Context& ctx, uint32_t capacity);   // HOST_VISIBLE | KERNEL_TIMESTAMP
  ~EventPool();
  EventPool(EventPool&&) noexcept;
  EventPool(const EventPool&) = delete;
  ze_event_pool_handle_t handle() const;
  uint32_t capacity() const;
 private:
  ze_event_pool_handle_t p_ = nullptr;
  uint32_t cap_ = 0;
};

// One timestamp event. Device signals it at kernel completion; host queries.
class Event {
 public:
  Event(EventPool& pool, uint32_t index);
  ~Event();
  Event(Event&&) noexcept;
  Event(const Event&) = delete;
  // Global (wall) kernel timestamps in device cycles, wrap-masked delta.
  // Returns microseconds. Query AFTER the fence that covers the launch.
  double duration_us() const;
  void reset();                                 // zeEventHostReset
  ze_event_handle_t handle() const;
 private:
  ze_event_handle_t e_ = nullptr;
};

// Device timer calibration, queried once per context.
// Uses ZE_STRUCTURE_TYPE_DEVICE_PROPERTIES_1_2 explicitly so timerResolution
// is pinned to cycles-per-second semantics; kernelTimestampValidBits masks
// the counter before any subtraction (32 bits on BMG wraps in seconds -
// durations only, never absolute times).
struct TimerCalib {
  double cycles_per_us;
  uint32_t valid_bits;
  static TimerCalib query(Context& ctx);
};
}  // namespace l0
```

- `CmdList::launch` gains a trailing default parameter - every existing call
  site compiles unchanged:

```cpp
void launch(Kernel& k, uint32_t gx, uint32_t gy = 1, uint32_t gz = 1,
            Event* signal = nullptr);
```

```cpp
// 1. TimerCalib::query returns cycles_per_us > 0 and valid_bits in [24,64].
// 2. Launch the launch_test kernel on a REGULAR list with a signal Event,
//    execute via Queue + Fence, then: duration_us() > 0 and < 1e6.
```

**Design (the documented Task-2 fallback, made concrete):**
- Stage A (`prep_res_fold`): grid `G = 20` work-groups × WG 256; work-group
