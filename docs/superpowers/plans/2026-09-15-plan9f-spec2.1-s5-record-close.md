# Spec 2.1 / S5 - pre-registration, the recorded rows, the default flip and the close Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pre-register the performance expectation, take the pp4096 rows on both backends at the harness's grade, flip the default backend to L0, run the whole suite, record everything, and tag `spec2.1-done` if - and only if - every bar of spec §2 is met.

**Architecture:** Measurement discipline, not code: one pre-registration commit before any timed row; the rows through `tools/bench_decode.sh` on device 0 (the series device); one profiled run per backend as a diagnostic; the flip is a one-line change in `backend_sycl.cc` plus the CLI's help text; the full suite runs AFTER the flip so bar 4 is proven for the shipped default.

**Tech Stack:** `tools/bench_decode.sh`, `b70-decode --bench --pp`, ctest, `docs/BENCHMARKS.md`.

**Spec:** `docs/superpowers/specs/2026-09-15-spec2.1-l0-prefill-gemm-design.md` (§2 bars 4-5 and the stopping rule, §5 S5, §8 risks 2, 3, 6)

## Global Constraints

- Branch `spec1.7-codex-exp`; never push (the tag is local too). Every commit message ends with `Claude-Session: `.
- Build/test only via `tools/box.sh`; the suite and the rows run detached and are polled.
- Never docker; never kill a process you did not start; never delete anything on the box.
- **The rows run on device 0** (the box-idle protocol: series rows stay on device 0; device 1 is 3.4% slower on prefill). Everything else on device 1.
- **Pre-registration precedes measurement; one defect, one fix, one measurement; the first correct build's number is the number.** Every number labelled measured / derived / estimated, with the harness's grade word quoted verbatim, never upgraded.
- The stopping rule (§2): any bar short → a memo to the operator in §10 and NO tag; no tuning pass without a ruling.
