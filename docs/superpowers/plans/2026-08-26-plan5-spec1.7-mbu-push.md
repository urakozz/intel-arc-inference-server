> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Raise decode MBU from 72.5%/69.6% to ≥82% on the running checkpoint
(≥ ~31.5 t/s Vishva-class, ≥ ~33 t/s int4-lm_head) - or deliver the priced
memo that says why not - by attacking the measured message-issue wall,
the attention family, and launch count, probe-first.

**Architecture:** Stage 0 prices everything: a wide/2D-block-load GEMV probe
battery (the builtins are verified to compile for BMG), a comparative vLLM
kernel timing at our shapes, and the `--profile` lever-spread settler.
docs/15 §1.7 re-ranks the ladder from those numbers. Stage 1 cuts levers
under the tie-aware golden gate; Task 8 is the gate: win → record + tag;
short → memo with the re-examined 90%-ceiling answer.

**Tech Stack:** OpenCL C 3.0 (+ `cl_intel_subgroup_2d_block_io`, verified),
ocloc AOT, pure Level Zero runtime, C++17, ctest on the box
(box, `tools/box.sh`), the operator's vLLM container (read-only)
for the comparative probe.

**Spec:** `docs/superpowers/specs/2026-08-26-spec1.7-mbu-push-design.md`
(read first - §1's decomposition and §2's rulings govern every task).

  variant BEFORE running (if messages bind: vec128 → ~+8-10% on the 533
  shapes; blk2d → toward the 584 ceiling; if bytes bind: all flat).

    dequant arithmetic unchanged; outputs must match baseline within the
    established gemv bar (bit-exact if order preserved - state which).

    control (same registers, no prefetch) - the attention probe's M1
    lesson.
- [ ] **Step 4: Run the battery** at the six shapes, idle box, base
  re-measured at battery end (drift control), box conditions recorded.
