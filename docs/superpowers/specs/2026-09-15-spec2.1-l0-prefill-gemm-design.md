# Spec 2.1 - a pure Level Zero prefill GEMM (our DPAS kernel beside sycl-tla)

Status: **design, 2026-09-15, for operator review.** Brainstormed with the operator the same day.
Every design choice below was ruled section by section; §9 records the rulings.

Spec 2 built the 27B's prefill. Its GEMMs go through sycl-tla on a SYCL queue that shares the
device's one compute queue with our Level Zero kernels. This spec adds a second prefill backend:
**every GEMM a chunk runs moves onto the Level Zero list as our own OpenCL C DPAS kernel, the int4
linears are dequantised and multiplied in 1024-column slabs with no host wait, and a chunk calls
no SYCL at all.**

It builds on the Phase 2 probes P-A and P-B (`docs/probe-prefill-vllm-parity-2026-09-14.md`,
pre-registered in `6501dd1`, measured in `35c9081` and `f7c3e5a`). sycl-tla stays selectable and
is the default until this spec's bars pass. It is a lever on spec 2, numbered like specs 1.5-1.7;
"spec 5" stays reserved for K2-Horizon's prefill.

Every number is **measured** unless marked **derived** or **estimated**.

## 2. Goals, bars, stopping rule

**Goal:** the 27B prefills through a pure Level Zero backend. Its output is equal to sycl-tla's, and pp4096 is measurably faster.

**Hard bars:**
1. **Kernels.**
   - `pf_gemm` is bitwise equal to sycl-tla's `gemm_bf16` / `gemm_bf16_batched` on identical inputs, at every production linear shape at M ∈ {2048, 772, 40} (a full chunk; the 2820-id long prompt's last chunk at C = 1024; a golden-prompt-sized chunk below one tile), and at both attention GEMMs at depths {64, 1000, 4096, 16384}, with and without transposed B. Only the first M rows and the first N columns are compared: the padding is by construction unread.
   - `pf_dequant_slab` is bitwise equal to `pf_dequant_tile`'s columns, for both weight layouts.
   - Every `pf_gemm` variant passes the build gate (§3.1).
2. **Backend equivalence.** Prefilling on each backend leaves the KV caches, GDN state, conv ring, the last logits row and `cur_token` **bitwise equal, counting +0.0 and −0.0 as equal**. The number of sign-of-zero differences is printed. The cases:
   - the three golden prompts, each a ragged single chunk;
   - a deterministic 4096-id prompt at C = 2048: two full chunks, the bench shape;
   - a mixed session: the prose prompt at `--pp-chunk 16`, alternating backend chunk by chunk, against a single-backend session.
3. **Model gates on the L0 backend:**
   - `prefill_gate_test` 93/93 determined rows exact, with undetermined rows inside the tie set;
   - `prefill_consistency_test`;
   - `prefill_determinism_test`.

   All three pass in the full build **and** in a build configured without the SYCL component.
4. **Nothing else moved.**
   - The decode list is 774 launches / 19 modules, `golden_gate_test` 93/93, and the full suite is green.
   - The sycl-tla backend's `prefill_gate_test`, `prefill_consistency_test` and `prefill_determinism_test` print identical token ids, metrics and verdict lines before and after stage S1's context split (timing lines excluded from the diff).
5. **Performance, pre-registered before the first timed row:** pp4096 (2 × 2048) with `--pp-backend l0` is **≥ 1480 t/s at RECORD grade**, device 0, median of 3 (`tools/bench_decode.sh`). A sycl-tla row in the same session is recorded as the control. RECORD is the harness's own verdict (zero containers, zero DRM holders); S5 waits for an idle box. If the operator's CPU-only buildkit build of 2026-09-15 is still running, the row is still taken, the harness's printed grade is recorded verbatim beside the operator's ruling that the build may be ignored, and the operator rules on the bar.

**Derived expectation, not a bar:**
- 2912.9 − 2 × 89.29 = 2734.3 ms → **~1498 t/s** from P-B's measured saving alone;
- **~1529 t/s** with the estimated GEMM credit;
- attention's change is unpriced, counted as zero.

The 1480 gate is the measured-only expectation less about one run's spread.

**Stopping rule:** all five bars met → the closing commit flips the default backend to L0 and tags
`spec2.1-done`. Any bar short → a memo to the operator; no tuning pass without a ruling.

## 3. Design

### 3.1 The production GEMM kernel - `src/kernels/prefill/pf_gemm.cl`

P-A's kernel is promoted with its tile, subgroups, DPAS loop, 2D block loads, prefetch and split barrier **unchanged**. It is generalised in three ways, all runtime arguments except the transpose:

| call site | M | K | N | batch | B layout |
|---|---|---|---|---|---|
| int4 linears, via slabs | C | 5120 / 6144 / 17408 | 1024 | 1 | the slab `[K][1024]` |
| attention Q·Kᵀ | C | 256 | depth | 6 q-heads | KV cache row `[4][256]`, **transposed** |
| attention P·V | C | depth | 256 | 6 | KV cache row `[4][256]` |

- **Arguments:** `M, K, N, lda, ldb, ldc, strideA, strideB, strideC`. The batch index is the launch grid's **z** dimension, so a batched GEMM stays one launch.
- **Transposed B** is a second binary (`TRANSB=1`), for Q·Kᵀ reading the KV cache in place. The mechanism: B stored `[N][K]` (K contiguous) is read as a 32-bit `[N][K/2]` surface with the LSC **transposed** 2D block load; each 32-bit element already holds the (k, k+1) pair the DPAS B operand wants, so the transposed load yields the VNNI fragment directly, with no shuffles. sycl-tla's ColumnMajor-B chain (`XeGemmT`) does the same. The dpas instructions, k order and accumulation are unchanged, which is why bitwise equality with the untransposed kernel is expected. Confirming the intrinsic name and the fragment order against the assembly is S0's first step.
- **Ragged edges are padded, never handled by a tail kernel.**
  - The caller rounds M and N up to a multiple of 256. Every buffer these GEMMs touch is already sized to a 256 multiple: chunk rows `kC = 2048`, `max_len`, every linear N.
  - The extra rows and columns are computed and never read.
  - K is 256, 5120, 6144, 17408 or a 256-padded depth, all multiples of 32.
  - One measured inner loop is kept instead of adding an unmeasured second one.
  - The L0 backend requires `max_len % 256 == 0` and throws otherwise.
- **The slab form is the same kernel:** B pitch = 1024, and C pre-offset by the slab's first column with `ldc` = the linear's full N. P-B's separate `pf_gemm_bf16_slab` entry point folds in.
- **Build gate:** every variant is AOT-built with `-cl-intel-256-GRF-per-thread`. Before any timing counts, the build output must show `grf_count 256`, `has_dpas true`, no `spill_mem_size`, no `private_size`, and 32 `dpas.8x8` per k-tile (the addendum's §A4.8 check).
- **2D block IO rules, asserted at the call:**
  - every surface pitch is a multiple of 16 bytes (`pf_q` 6144×2, KV 1024×2, `pf_s`/`pf_p` max_len×2 or ×4, `pf_o` 256×4, linears K×2 and N×4);
  - every batch base address is a multiple of 64 bytes.

`src/kernels/prefill/pf_dequant_slab.cl` is new, promoted from the slab probe's dequant. It expands columns `[n0, n0 + 1024)` of one int4 weight into a bf16 `[K][1024]` slab, for layout 0 and layout 1, compiled per shape like `dequant.cl`. The existing `dequant.cl` is not edited.

### 3.2 The switch - a narrow backend seam (operator ruling: option 1)

`enum class PrefillBackend { SyclTla, L0 }`. The step walk (`step.cc`) and attention (`attn.cc`)
branch on it at exactly two places:
- **`pf_linear`:**
  - `linear_sycl` is today's body moved **verbatim**: `dequant_to_bf16`, timed wait, `gemm_bf16`, timed wait.
  - `linear_l0` is the slab walk (§3.3).
- **Attention's two GEMMs:**
  - on sycl-tla, the existing `gemm_bf16_batched` calls and their waits;
  - on L0, `pf_gemm` (§3.4).

Norms, GDN, a‖b, the softmax, the gate, `lm_head` and argmax are shared and not edited. There is no virtual interface: two backends do not need one. The launch-count helpers (`step_chunk_launches()`, `step_chunk_gemms()`, `step_chunk_waits()`) take the backend.

### 3.3 The int4 linears on L0 - the slab walk

For `n0 = 0, 1024, … < N`:
1. `pf_dequant_slab` writes columns `[n0, n0 + 1024)` of the weight into the slab buffer;
2. `pf_gemm` multiplies `x [M][K]` by the slab into `partials` from column `n0`;

both appended to the same in-order immediate list, with **no host wait** between them, between slabs, or before the next kernel reads `partials`.

- **Slab counts** (all exact, no partial slab): gate‖up 34, qkv‖z 16 (layout 1: 64 whole 16-column tiles), q‖k‖v 14, out_proj / o_proj / down 5 each.
- **Launches per chunk:** 1201 today → **8689** on L0 (derived: GDN layer 20 − 4 + 120 = 136, FA layer 15 − 4 + 116 + 8 = 135, plus embed). P-B's measured saving already includes the per-launch host cost of its slab loop.
- **Memory:** the slab buffer `[17408][1024]` bf16 = **35,651,584 B** (derived: 17408 × 1024 × 2). Today `PrefillScratch::dequant` (356,515,840 B) is a fixed member allocated with the scratch. Both buffers become lazily allocated members of `PrefillScratch`: the dequant buffer on the sycl-tla backend's first linear, the slab buffer on the L0 backend's first (ruling R7's pattern, one level down). `buffers_test`'s pinned `PrefillScratch` total is restated without either buffer, and each backend prints its resident bytes at its first prefill. On L0 the prefill scratch is **320.9 MB smaller** (derived).
- **Width:** fixed at 1024, the measured best; 2048 measured +40.91 against 1024's +89.29.

### 3.4 Attention on L0

Per kv-head group, on the one list:
1. `pf_gemm` (`TRANSB=1`) for Q·Kᵀ over the 6 q-heads (B stride 0: GQA's shared kv-head);
2. `pf_softmax_causal`, unchanged;
3. `pf_gemm` for P·V over the 6 heads.

`attn_prep_chunk` is unchanged. `attn_gate_chunk`'s kernel is unchanged; its `stride_h` argument follows the padding rule below. The number of kernel executions per FA layer is unchanged: the 8 attention GEMMs become Level Zero launches instead of SYCL submissions, and host waits go from 9 to 0.

**Padding:**
- Q·Kᵀ uses M = C and N = depth, both rounded up to 256 (today depth is padded to 8).
- **Every attention buffer's per-head slot stride uses the padded row count `M256 = ⌈C/256⌉·256`, not C.** On the L0 backend that covers `pf_s` and `pf_p` (`M256 × max_len`) and `pf_o` (`M256 × 256`), as passed to both GEMMs, the softmax's `stride_l` and the gate's `stride_h`. A batched launch computes every head's padded rows at the same time, so a stride of `C × width` would let head l's padded rows overwrite head l+1's valid rows. `M256 ≤ kC = 2048` keeps every slot inside today's allocations.
- The softmax receives the 256-padded width as `npad`. `pf_attn.cl` uses `npad` only as the end of its +0.0 zero-fill; valid columns come from `nvalid = pos + m + 1`, so every value read downstream is unchanged.
- P·V uses K = the padded depth. The extra P columns are exactly +0.0 and come after every real term in ascending-k order, so they add nothing.
- **The invariant this leans on:** P·V multiplies those +0.0 weights by KV rows `[depth, depth256)` that this session has not written, and `0 · NaN` would poison the row. Every KV slot is zero (`reset()` zeroes the caches) or a finite value written by `attn_prep`, so the product is an exact zero. Today's sycl-tla path already relies on this at 8-column granularity (`npad`); this spec widens it to 256 and states it. The decode kernels never read an unwritten slot.

**The one expected difference from sycl-tla:** a P·V sum that is exactly −0.0 becomes +0.0. Bar 2 counts such elements rather than hiding them.

### 3.5 Context without SYCL, and the build

Today `runtime::prefill::Context` lives in `libb70_prefill.so` (icpx). It owns the Level Zero immediate list and a SYCL queue, and `wait()` synchronises both. `b70_prefill_host`, and `Engine::prefill` with it, exists only when the SYCL component is enabled.

- **`Context`** keeps its interface and becomes pure Level Zero: list, `launch`, `wait`, launch count. It is compiled with g++ into `b70_prefill_host`.
- **`SyclSide`**, in `libb70_prefill.so`, owns the SYCL device, context and queue. The prefill engine creates it **only when the sycl-tla backend is selected**. When present, `wait()` synchronises the SYCL queue and then the list, today's order.
- **CMake chooses the source:**
  - with the SYCL component, `prefill_sycl.cc` provides `linear_sycl`, the batched sycl-tla calls and the `SyclSide` factory;
  - without it, `prefill_sycl_absent.cc` provides the same functions and they throw "this build has no SYCL component";
  - no `#ifdef` in the step.
- **Result:** `b70_prefill_host`, `Engine::prefill`, `--pp` and `--prefill` exist in every build, and the L0 backend runs in a build without icpx. Decode-only binaries and tests still link nothing from prefill.
- **Selection:**
  - `Engine::set_prefill_backend(PrefillBackend)`, changeable between `prefill()` calls; persistent state is shared, scratch is per backend.
  - `--pp-backend sycl-tla|l0` on `b70-decode` (`--pp`, `--prefill`, the bench rows) and `b70-serve`; `tools/bench_decode.sh` passes it through and prints it in its header.
  - **Default** during the spec: sycl-tla when built, otherwise L0. The closing commit sets L0 unconditionally, only if every bar passes.
- **Profiling:** per-phase attribution keeps inserting waits between phases on both backends. It is a diagnostic and never a bench row, so the zero-wait property is a property of the timed path only.

## 4. Correctness (how each bar is proven)

- **Kernel tests** (`tests/prefill/pf_gemm_test.cc`, `pf_dequant_slab_test.cc`):
  - `pf_gemm` against sycl-tla's GEMMs in the same process, on identical incompressible bf16 inputs, `memcmp` equality, at the shapes in bar 1;
  - `pf_dequant_slab` against `pf_dequant_tile` over every slab of one production matrix per layout;
  - the build gate is checked on each variant's dumped `.zeinfo`.
- **`prefill_backend_equivalence_test`:**
  - the cases in bar 2; after each prefill, read back `kv_k`, `kv_v`, `gdn_state`, `conv_ring`, the last `logits` row and `Control`; compare with +0/−0 equal; print the sign-of-zero count.
  - Needs both backends, so it is registered only in the full build.
- **Model gates:** the existing three prefill tests take a backend argument. They are registered twice in the full build (once per backend) and once (L0) in a second build directory on the box, `build-nosycl`, configured with `-DB70_PREFILL=OFF`; `tools/box.sh` gains a way to name that directory.
- **Nothing else moved:** the full suite, the decode invariants, and a before/after diff of the sycl-tla prefill tests' printed outputs around stage S1.

## 5. Stages

- **S0 - kernels.** `pf_gemm.cl` (and its `TRANSB` variant, whose transposed-load intrinsic and fragment order are confirmed against the assembly first) and `pf_dequant_slab.cl` with their tests and build gate → bar 1.
- **S1 - context split and switch.** `Context` / `SyclSide`, the absent-SYCL source, `Engine::set_prefill_backend`, `--pp-backend`, launch-count helpers, the lazy dequant buffer, and `context_test`'s 9,000-launch chain (risk 7). There is no L0 backend body yet (selecting L0 throws "not implemented"). The sycl-tla prefill tests' outputs must be identical before and after → bar 4, second half.
- **S2 - linears on L0.** `linear_l0`. Attention still goes through sycl-tla's GEMMs when present. The equivalence test covers the linears.
- **S3 - attention on L0.** The L0 backend asserts it never constructs `SyclSide` → the full equivalence test, bar 2.
- **S4 - model gates.** The three prefill tests on L0 in the full build and in the no-SYCL build → bar 3.
- **S5 - record and close.**
  1. Pre-register the row.
  2. Run the bench rows (L0 and the sycl-tla control), then the full suite.
  3. Update docs/BENCHMARKS.md and append a §10 close section to this spec.
  4. Flip the default and tag, only if bars 1-5 are all met.
