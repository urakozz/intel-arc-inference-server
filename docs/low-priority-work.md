| **TP + slots: several requests at once on the two-card tensor-parallel engine** (ruled out 2026-11-11, operator; branch `tp-slots`, Codex's build plus the fix agent's WIP) | One TP engine with sequence slots (one prefix cache, every slot's KV on both cards). | **A shared paged KV pool instead of fixed slots** (considered and postponed 2026-11-11, operator) | vLLM-style: one pool of small KV blocks shared by all requests; any request may grow to `--max-len` while the others stay small, so several medium sessions fit where fixed slots cannot (e.g. 3 x 60k beside each other). The workaround: the l0 prefill or the bf16 cache | Read the chunk's own new rows from bf16 inside the chunk (they are computed in bf16 anyway), older rows from int8 - no extra memory.
