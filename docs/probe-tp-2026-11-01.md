# Probe: tensor parallel over two B70s, Qwen3.8 first (spec 17 P0, plan 17a) - 2026-11-01

Spec: `docs/superpowers/specs/2026-10-05-spec17-tensor-parallel-design.md` (§R2; the go / no-go rule §R2.7, the
verdict §9). Plan: `docs/superpowers/plans/2026-10-05-spec17a-tp-probe.md`. Box queue row 71. Probe:
`tools/probe/probe_tp` (`probe_tp.cc`, kernels `probe_tp.cl`, protocol `tp_protocol.h`, shapes `tp_shapes.h`).

**Grades** (spec 17's legend): measured / derived / estimated / assumed / published.

**Timing grade of this record: busy-box timing, re-check on a quiet box.** The operator moved the project to parallel
development on 2026-11-01: 8+ agents share the two cards. Every two-card stage ran under `tools/gpu_lock.sh box` (both
cards ours for the stage, nothing else on them), each window under 10 minutes, but the CPU and the host carried other
agents' work (the load average is printed with every table; DRM holders were the desktop's ptyxis / Xwayland / nautilus /
resources / chrome, which submit nothing). Every ratio comes from interleaved control / candidate lists after a warm-up,
median of 5 rounds with the range. The GO / NO-GO line below is **PROVISIONAL** until §7's re-check set runs on a quiet
box.

## 0. What was built

- `tools/probe/tp_shapes.h`: spec 17 §R2.5's split from `ModelDesc` through a `tp_rank` / `tp_size` view - the
  all-reduce count (2 a layer: Qwen3.8 128, Agnes 144, + the head's exchange), the row (hidden x fp32 = 20 KiB), the
  per-card linears (every K slice whole 64-groups, the fused qkv‖z / q‖k‖v re-fused per card from the card's heads).
  `tests/kernels/tp_shapes_test.cc`. Dense GDN hybrids only (a MoE model and an uneven split are refused).
- `tools/probe/tp_protocol.h`: the crossing protocol as host code (fold-then-send, two slots a destination, a trailer
  stamp per chunk with the data, a flag per chunk on its own line, per-work-group counters advanced by the kernels so
  replays progress, bounded spins, the first failure kept, the fixed-order sum card 0 + card 1, the CPU's forward
  poisoned on a failure). `tests/runtime/tp_crossing_protocol_test.cc` runs every route on host threads (2000 calls at
  M = 1, 300 at M = 8, bitwise on both "cards"; a skipped data write caught as stale, a dropped write a bounded
  timeout).
- `tools/probe/probe_tp.cl`: `tp_send` (fold S split-K slices + a per-call term, write row + trailer + flag to the
  route's destination), `tp_wait` (bounded spin, trailer check, system-scope loads, the fixed-order add or take the
  CPU's sum; with `--replays` every word checked against the host formula and hashed for the cross-card compare),
  `tp_ping` (the BAR round trip).
- `probe_tp facts | bar | ar | step` (header of `probe_tp.cc`), and 8 probe-only `ptp_gemv_*` binaries: today's
  `gemv.cl` / `gemv_i8w.cl` at the per-card shapes with the one-card production cells' defines.
- No `src/` change: `tools/kernel_cmdlines` +0 / -0 / ~0 against main (`tools/mac_check.sh`).

### 3.3 What the card's memory model did (findings that bind 17b)

1. **A flag published with a system-scope atomic store (`atomic_store_explicit(..., memory_scope_all_svm_devices)`)
   reached the peer's VRAM** (p2p-push worked with it, 5.1 us a call) **but was never seen by any reader when it went
   to pinned host memory** - neither by the CPU nor by the other card - while the plain trailer store written before it
   was. A plain store followed by a second system-scope release fence (`tp_publish` mode 1, the default) works for
   both, and is 1.6 us a call cheaper on p2p-push (3.51 against 5.11 us).
2. **A card polling memory it does not own never sees the flag change**: the peer's VRAM (p2p-pull) and pinned host
   memory (host-mbox, host-read, the bar probe's host path) - with the allocation cached, uncached or write-combined,
   the device allocation uncached, with or without a list barrier after the send. The trailer, read once after the
   spin, is current: the poll is served from a cache line the first load filled, system scope or not. **Only a poll of
   the card's own VRAM works** - written by the peer (p2p-push) or by the CPU through the BAR (host-bar). Every working
   route therefore lands the data in the reader's own memory.
3. spec 16b's `pp_send` / `pp_recv` (pipeline parallel, `--pipeline-handoff peer`) push into the peer's VRAM and poll it
   locally - the working shape - but publish the flag with the atomic store of finding 1: still correct on push, 1.6 us
   slower a hand-off than the plain store.

**Card 0's half of route (H) runs at ~8.5 us** (its previous sum lands through the BAR, its wait notices it, its next
send reaches the mailbox, the CPU sees it) and the CPU's sum + two BAR writes take ~10 us at M = 1 (~78 at M = 8) - a

whether the row goes out by kernel stores or by the list's copies, with or without a barrier; the 160 KiB rows of M = 8
do not lengthen it (243 us), so it is a latency, not a rate. Card 1's own BAR round trip is ~3 us with a one-word host
ack (§2), so the delay is in card 1's 20 KiB+ write into pinned host memory inside a list (or in how the one context's
host allocation is reached from the second device) - not diagnosed (§6). Route (P) does not touch host memory, so it
does not decide the line.

## 6. Open

- Why card 1's writes into pinned host memory arrive ~290 us after card 0's on every call (§3.4) while its one-word
  host ack in the bar probe takes ~3 us: allocate the mailboxes per device, swap the cards' roles, time card 1's
  20 KiB host write alone. Not needed for the GO (route (P) is 70-95x cheaper than (H) as measured), recorded for a
  P2P-less platform; with card 1 at card 0's ~8.5 us, (H) would be ~20 us a call (~2.6 ms a token, derived).
- p2p-pull and every host-polling route fail because a card's poll of memory it does not own is served from a cache:
  if 17b ever needs them, the next things to try are a different load form (an atomic RMW poll - but P2P ATOMICS = no -
  or an `intel_sub_group_block_read` with an uncached cache-control hint) - not needed for route (P).
- `qkv‖z` per card at S1 L1 keeps 71 % of its bandwidth: re-tune its per-card cell (17b), worth ~0.8 ms a token
  (derived: 48 x (56.5 - 0.5 x 79.8) us).
- The `--under-load` link line (needs `probe_offload`, `-DB70_Q4EXP=ON`).
- The bar probe ran on physical card 1 only; the step on card 0 only.
